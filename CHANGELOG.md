# Changelog — DesktopEngine

## 2.2.0 (não publicada)

### Novas APIs do `Desktop`
- `closeAllWindows({ force } = {})`: fecha todas as janelas abertas (logout/encerramento — nada da app fica visível sem sessão); devolve `true` se todas fecharam, `false` se alguma bloqueou (só sem `force`). `closeWindow` ganhou `{ force }` (5º param opcional, propaga para a modal filha): `true` pula o `beforeClose`.
- `setWallpaper(value, persist)` / `getWallpaper()`: plano de fundo da área de trabalho (`#desktop`) — aceita URL de imagem (`cover` centralizado), `url(...)`, gradiente CSS ou cor; `null` restaura o fundo padrão do tema. Persistência opcional em `desktop_engine_wallpaper` (restaurada no `init()`), evento `desktop:wallpaperchange`.
- `desktop.js`: **modos de exibição do papel de parede** (estilo MS Windows) — `setWallpaper(value, persist, mode)` com `cover` (Preencher, padrão) | `contain` (Ajustar) | `stretch` (Esticar) | `center` (Centralizar) | `tile` (Lado a lado, mosaico); `getWallpaperModes()` (ids + rótulos) e `getWallpaperMode()`; modo persistido em `desktop_engine_wallpaper_mode` e restaurado no `init()`; apelidos em PT aceitos (`preencher`, `centralizar`, `lado-a-lado`...).
- `desktop.js`: **menus padrão do ambiente** — `getDefaultWindowItems()` (organizar + área de trabalho + mobile), `getDesktopContextItems({ extraItems, lafItems, includeWindows, appName, onAbout })` (botão direito no papel de parede: atalhos da app + LaF + janelas + sobre) e `getEnvironmentMenus({ sessionItems, lafItems, windowItems, includeWindows, aboutItems, appName, onAbout })` (seções Sistema/LaF/Janelas/Ajuda do Iniciar); a app injeta sessão, LaF e ajuda sem reescrever o boilerplate.
- `desktop.js`: **janela centralizada** — opção `centered: true` na config da tela (abre sempre no centro da superfície, ignorando a cascata; ex.: autenticação) + `Desktop.centerWindow(instânciaOuElemento, surface?)` (usa `width/height` declarados, trava em 0 sem posição negativa).
- `setMenuBarLabels(mode, persist)` / `getMenuBarLabels()`: exibição dos rótulos da MenuBar global — `auto` (padrão: trilho de ícones na lateral, rótulo vai para o tooltip) ou `labels` (rótulo sempre visível ao lado do ícone). Persistência opcional em `desktop_engine_menubar_labels`, evento `menubar:labelschange`.
- `css/core.css` (MenuBar lateral): itens com altura automática, fonte 12px e rótulo quebrado em até 2 linhas com elipse (`-webkit-line-clamp`) — elimina o estouro de texto na barra de 170px; regra do modo `data-labels="labels"`.
- `confirm(message, opts)` / `prompt(message, opts)` / `alert(message, opts)` (em `desktop.js`, sobre `Modal`): diálogos Promise que substituem os nativos — `confirm` devolve `Promise<boolean>` (false em Cancelar/ESC/fechar; `{ danger: true }` usa o botão `ui-btn-danger`), `prompt` devolve `Promise<string|null>` (null no cancelar; `{ value }` pré-preenche e Enter confirma) e `alert` resolve em OK/ESC/fechar. **Escopo:** `Desktop.confirm/prompt/alert` bloqueiam o Desktop inteiro; `win.confirm/prompt/alert` (ou a opção `{ instance: win }`) bloqueiam **apenas a janela** — o `Modal` é renderizado dentro do elemento dela. Os stubs de `_normalizeScreen` instalam `confirm/prompt/alert` no objeto-tela (delegam à instância viva; sem janela caem para o diálogo global) — dentro das telas basta `this.confirm(...)`.
- `_dialogScope(instance)`: helper interno que decide o escopo dos diálogos — `instance` de janela montada → modal local; caso contrário (sem instância ou janela já fechada) → modal global.

### Novos Serviços Genéricos
- `activity-service.js`: **ActivityService** — fila de atividades assíncronas com acompanhamento e exibição configurável (export `./activity-service`). A aplicação informa como iniciar (`run` local com `act.setProgress(v, msg)` ou `request` via `ApiService` com `getJobId`), como acompanhar (`watch` por poll com `isDone`/`isFailed`/`progress`/`extract` padrão para `{ status }`, ou por push com `subscribe` do transporte — `auto` escolhe pelo transporte, com normalização `{ event, data }` nos 3 transports e filtro `event`/`match`) e onde exibir o resultado (`target`: `dock|window|modal|toast|none|função`, `track`: `dock|none`). Fila FIFO com `maxConcurrent` (padrão 3), dedupe por `id`, dock de acompanhamento (agrupado por `targetOptions.dock.id`, senão um por atividade; criação lazy, badge de pendentes, `attachDock` para o dock da app que o serviço nunca fecha), persistência em `desktop_engine_activities` com retomada no `init()` (exige `registerSpec`, pois funções não serializam; sem spec, ativa vira histórico passivo), teto `historyLimit`, eventos `activity:*` via `emitLocal` e `promise`/`cancel()`/`retry()` por atividade. A mensagem de status usa `watch.message(res, act)` ou, por padrão, o campo `message` da resposta. API: `configure`, `registerSpec`, `getSpec`, `enqueue`, `get`, `list`, `cancel`, `retry`, `present`, `remove`, `clear`, `attachDock`, `getDock`, `detachDock`, `init`, `reset`.
- `auth-service.js`: **AuthService** — autenticação genérica com provedores registráveis (email/senha, SSO, LDAP, etc.). Gerencia sessão, persistência e eventos de autenticação. API: `registerProvider`, `removeProvider`, `getProvider`, `listProviders`, `login`, `logout`, `setSession` (define/restaura sessão sem passar por `login`; `null` encerra em silêncio), `isAuthenticated`, `getCurrentUser`, `getCurrentProvider`, `getSession`, `getToken`, `init`, `updateSession`.
- `api-service.js`: **ApiService** — cliente de dados genérico com transportes registráveis (HTTP, WebSocket, SSE, gRPC, etc.). Gerencia interceptors, transporte padrão e métodos de conveniência. API: `registerTransport`, `setDefaultTransport`, `request`, `get`, `post`, `put`, `patch`, `delete`, `onRequest`, `onResponse`, `onError`.
- `element-permission-plugin.js`: **ElementPermissionPlugin** — plugin nativo para permissões de elementos de UI. A aplicação configura a fonte de permissões e o modo edição, e o framework aplica hide/disable nos elementos sem permissão e filtra itens de menu. API: `load`, `clear` (limpa o catálogo e marca como não carregado — use no logout, em vez de recarregar sem sessão), `isAllowed`, `applyToContent`, `isMenuItemAllowed`, `rowsForScreen` (linhas do catálogo por tela, para o inspetor checar duplicidade/edição), `reapplyOpenWindows` (reaplica em todas as janelas abertas via `data-screen-id`), `refresh` (recarrega **e** reaplica — ponto de sincronização após mutação no catálogo), `isLoaded`.

### Provedores de autenticação e transporte HTTP prontos
- `auth-providers.js` (novo módulo): provedores "meio caminho andado" para o `AuthService` — o dev só registra credenciais/endpoints: **`createOAuthProvider`** (OAuth2/OIDC Authorization Code + PKCE: URL de autorização com `state`/`code_challenge` S256, OIDC Discovery via `issuer`, troca `code`→token, perfil via `userinfo_endpoint` ou payload do `id_token`, `mapUser`, revogação opcional, limpeza da URL), **`createSsoProvider`** (redirect pelo backend com `?token=` + `fetchUser`), **`createLdapProvider`** (bind validado no backend via POST JSON, `extract`/`mapUser` configuráveis) e `parseSearch`.
- `auth-service.js`: **`handleCallback(providerName, ...args)`** — processa o retorno do IdP (`?code=`/`?token=`): cria e persiste a sessão com evento `auth:login` só quando o provedor devolve resultado (`null` = não é callback, não interrompe o boot). `login()` agora aceita retorno `null` (provedores de redirect navegam para o IdP e a sessão vem no callback) e `logout()` passa a sessão ao provedor (para revogar token no IdP).
- `api-service.js`: **`createHttpTransport(config)`** — transporte HTTP pronto para o `ApiService` (`baseUrl`, `getToken`, `headers` padrão, `fetch` injetável) com query string, `204 No Content` e erros padronizados; **`ApiError`** exportada com `message`/`status`/`data`. A aplicação só registra com a configuração dela.
- `api-service.js`: **`createHttpTransport` com `options.responseType`** (`'json'` padrão | `'blob'` | `'arrayBuffer'` | `'text'`) — o transporte HTTP pronto agora baixa binários autenticados (Bearer do `getToken`, `Accept: */*`, erros ainda em `ApiError`); combina com `downloadFile` do `format.js` para downloads (ex.: PDF).
- `api-transports.js`: transportes prontos para o `ApiService` — **`createWebSocketTransport`** (request/response por id de correlação, fila antes do open, timeout em `ApiError`, reconexão com backoff exponencial, `subscribe()` para push e `close()`/`getStatus()`), **`createSocketIoTransport`** (adaptador padrão do NestJS — `io`/`socket` injetáveis sem depender do `socket.io-client`, handshake com token via `getToken`, RPC por **ack** do Socket.IO ou por **`replyEvent`** com id, `cfg.events` + `subscribe()` para push, `timeout`/`close`), **`createSseTransport`** (`subscribe(endpoint, handler)` → `{ event, data, lastEventId }`, `request()` resolve ao conectar, `DELETE` fecha o stream, token/params na query, eventos nomeados via `cfg.events`) e **`createMockTransport`** (rotas `'MÉTODO /caminho'` com `:param`, handlers sync/async, latência simulada, erros via `throw new ApiError`, `addRoute`/`removeRoute` e `fallback` customizado). Export `./api-transports`.

### Formatação, CSV e padrões de UI
- `format.js` (novo módulo, export `./format` no `package.json`): utilitários genéricos de apresentação com instâncias `Intl` em cache — `formatCurrency` (pt-BR; dado ausente → `fallback` `'—'`, zero explícito → `'R$ 0,00'`), `formatNumber`, `formatDate` (`dd/mm/aaaa`), `formatDateTime` (data + hora sem segundos por padrão; `{ seconds: true }`), `formatBytes`, `statusColor(status, map, fallback)` (padrão `{ bg: '#f3f4f6', color: '#374151' }`), `buildCsv` (BOM UTF-8, delimitador `;`, CRLF, escape de aspas), `downloadFile(name, content, mime)` e `downloadCsv(name, rows, { columns })` (Blob + âncora com `revokeObjectURL`).
- `ui/patterns.js` (novo, re-exportado pelo barrel `ui.js`): `FilterBar({ search: { placeholder, value, onInput, onSearch, buttonLabel }, children, actions, instance })` (busca + `children` no meio + `actions` no fim; sem `onSearch` não cria o botão "Buscar"), `EmptyState({ icon, message, hint, action })` (`action` é um nó pronto ou `{ text, onClick, variant }`) e `KpiCard({ label, value, icon, color, hint })` (`color` vira a borda esquerda do card; valor vazio → `—`) — primitivas prontas para telas de listagem e painéis.
- `css/core.css`: classes novas `.ui-filter-bar`/`.ui-filter-search`, `.ui-empty-state`, `.ui-kpi-*`, `.ui-dialog-*` e `.ui-btn-danger` (botão destrutivo dos diálogos `danger`).
- `css/core.css`: classes novas `.ui-activity-item`/`.ui-activity-icon`/`.ui-activity-main`/`.ui-activity-title`/`.ui-activity-sub`/`.ui-activity-side`, `.ui-activity-btn` e `.ui-activity-pre` (linhas da fila do `ActivityService` no dock + JSON do target modal).

### Correções
- `README.md` / `docs.html` (exemplo do hook `beforeClose`): o exemplo chamava `Modal.confirm(...)` — API inexistente no framework. Agora usa `this.confirm(msg, { danger: true, okLabel, cancelLabel })` (diálogo Promise no escopo da janela, que cancela o fechamento com `false`), alinhado ao padrão documentado de `Desktop.confirm`/`win.confirm`.
- `css/core.css` (`.ui-modal-overlay`): o overlay do modal global (`Desktop.confirm/prompt/alert`) estava em `z-index: 400000` — abaixo do menubar global e seus dropdowns (`500000`/`500002`) — então o menubar continuava clicável por cima do diálogo ("bloqueia o desktop todo" pela metade). Agora fica em **`600000`**, acima de todo o shell (menubar, start menu, taskbar, menus de contexto) e abaixo apenas dos toasts (`999999`); o modal no escopo da janela (`win.confirm/openModal`) não muda — é filho da janela e o valor é relativo ao contexto de empilhamento dela. Regressão coberta em `test/layers.spec.js`.
- `core.js` (foco em re-render): o `update()` da janela só restaurava o foco de campos com `data-bind`; um input com só `data-eid`/`id` era recriado pela atualização do estado e o usuário **perdia o foco a cada tecla**. Agora o foco é salvo/restaurado por `data-bind`, `data-eid` ou `id` — e sempre com a posição do cursor. Mesmo ajuste no `BaseComponent.update()`.
- `ElementBuilder.js` (`on()`): quando o campo tinha `data-bind`, o handler do desenvolvedor era **substituído** pela atualização silenciosa — efeitos colaterais (recalcular campos, `safeUpdate`, etc.) se perdiam. Agora a atualização silenciosa roda **e** o handler é executado.
- `core.js` (proxy de estado): atribuir o **mesmo valor** não dispara mais re-render (evita cursor jump quando o handler reassina o estado já sincronizado pelo binding).
- `desktop.js` (estado fresco por abertura): `config.state = windowInstance.state` fazia o estado vivo da última janela virar a base da próxima abertura — os valores digitados **vazavam** para a tela reaberta. Agora `_normalizeScreen` guarda o estado **declarado** (`config._declaredState`) e cada abertura clona o template (`cloneState`, profundidade para objetos/arrays; Signals/instâncias por referência); vale para `openScreen` e `openDialog`.
- `ui/patterns.js` (`FilterBar`/`EmptyState`) e `ui/core-dom.js` (`createElement`): filhos/builders passados como `ElementBuilder` eram **descartados silenciosamente** (só `Node` era aceito) — por isso barras de filtro das telas apareciam vazias. Agora aceitam nó, builder (`.build()`), `{ el }` e arrays, normalmente.
- `ui/feedback.js` (`Modal`): `onClose` **função** era ignorado quando o `Modal` tinha `instance` (tratava a função como nome de action e chamava `instance.runAction(onClose)`) — o cancelar/fechar do modal por janela nunca resolvia a Promise dos diálogos. Agora função executa direto e só string passa pelo `runAction`.
- `ui/navigation.js` (`DockWidget`): **empilhamento automático** dos docks globais do mesmo canto (mais novo acima do anterior, gap 12px, altura viva medida; re-layout em `toggle`/`setContent`/`addItem`/`clear`/`minimizeToTray`/`restoreFromTray`/`close`/`destroy`/`resize`; minimizados não ocupam espaço; docks locais fora) e **corpo com teto de viewport** (`min(height, calc(100vh - 160px))` — cresce com o conteúdo até o limite da área de trabalho, depois rola por dentro).
- `ui/navigation.js` (novo): **`DockContainer`** — painel fixo do canto com barra de rolagem que hospeda DockWidgets (`attach`/`detach`, `container` no `DockWidget`, `Desktop.createDockContainer`); badge = visíveis, expande sozinho no 0→1, recolhe ao esvaziar, participa da pilha do canto; `ActivityService.attachContainer/detachContainer/getContainer` (docks próprios moram nele, inclusive os já abertos) e **`configure({ dockContainer: true|{...} })`** (o serviço cria a Central sozinho, lazy; `attachDock(id, api, { container: true })` hospeda o dock da app).
- `ui/navigation.js` — **`DockContainer` com menu de contexto**: nova opção `contextMenu` (`null` = padrão, removível só quando vazio | `true` = sempre removível | array | `(api) => array`; itens próprios ganham `Remover painel` anexado quando vazio), `setContextMenu(items)` em tempo de uso e `onClose` (disparado no `close()`); botão direito no painel vazio oferece `🗑️ Remover painel`; o ícone minimizado na taskbar também tem menu (botão direito: `🔼 Restaurar painel` + `🗑️ Remover painel`).
- `ui/navigation.js` (`ShortcutContainer`): alinhamento por eixo em `direction: 'column'` — `alignH` agora controla `align-items`/`align-content` (horizontal) e `alignV` o `justify-content` (vertical); antes os eixos ficavam trocados no modo coluna e a coluna de atalhos encostava à esquerda em vez de preencher da direita para a esquerda. `setAlignH`/`setAlignV`/`setDirection` reaplicam pelo eixo correto (a troca de `direction` troca os eixos junto). Em `column` com `alignH: 'right'` o contêiner ganha `direction: rtl`: as colunas quebradas pelo `wrap` nascem encostadas na borda direita e crescem para a esquerda — **o preenchimento acontece da direita para a esquerda**.
- `css/core.css` (`.ui-shortcut__label`): rótulo dos atalhos sem `text-shadow` e com peso normal (400) — a tipografia passa a ser a mesma do MenuBar (fonte do tema herdada do `body`, sem sombra nem negrito). `.ui-shortcut` fixa `direction: ltr` para os rótulos não embaralharem quando o contêiner fica rtl.
- `css/themes` (23 temas): bloco na raiz declarando **`--font-family`** (fonte assinatura do tema, extraída de `.window`/`.titlebar`) — o `core.css` aplica `var(--font-family)` no `body`, então agora a área de trabalho, os atalhos e qualquer elemento sem fonte explícita usam a fonte do tema; antes só componentes com regra própria (`.window`, `#taskbar`…) recebiam e os atalhos ficavam em Segoe UI.
- `css/core.css` (modo mobile): MenuBar nas posições `left`/`right` vira **trilho estreito de `48px` mantendo a lateral escolhida** (a coluna de `170px` estourava a tela estreita; a faixa no topo descartava esquerda/direita) — `grid-template-columns` encolhido para `48px` em todas as combinações de taskbar (top/bottom/lateral), barra com altura total (anula o `height:48px` da faixa horizontal) e o **hambúrguer ☰ no topo da coluna** (comportamento mobile padrão: abre o drawer de menus; alvo de toque `44px`), itens ocultos como no resto do mobile. O bloco é espelhado **dentro de `@media (max-width: 768px)`** (sem a classe `.mobile-mode`), para valer também no viewport estreito (F12/responsivo), como o resto das regras mobile.
- `css/core.css` (menubar lateral): centralização (`justify-content: center` + `padding: 0`) dos itens com ícone nas posições `left`/`right` — sincronizado a partir da cópia do app.
- `desktop.js` (`openScreen`): removido `async` desnecessário — telas registradas como objeto agora retornam síncrono (como documentado), telas lazy (função) continuam assíncronas via Promise.
- `test/openscreen.spec.js`: `beforeEach` agora chama `Desktop.init()` quando necessário, corrigindo falha pré-existente por `windowsEl` null.
- `ui/navigation.js` (`extractScreenId`): aceita aspas simples **e** duplas — bundlers (esbuild/Vite) normalizam `toString()` para duplas, o que quebrava a detecção (sem menu contextual e sem filtro de permissão).
- `desktop.js` (`registerStartMenu`): passa os menus **crus** ao `setStartMenu` (mesclagem só no render). Antes passava o efetivo já mesclado, que o `StartMenu` gravava de volta no registro — cada ciclo duplicava as opções no modo mesclado.
- `css/core.css`: grade explícita do `#app` para menubar lateral (left/right) × taskbar em cima/baixo/ausente/laterais (10 combos). Sem ela, o `#app` caía em `flex-direction: row` e a taskbar (`width: 100%`) quebrava o layout / escondia a barra.
- `desktop.js` (`_normalizeScreen` + `config._instance`/`config.state` em `_finishOpenScreen`/`openDialog`): o objeto-tela original fica ligado à instância viva da janela — `Tela.metodo()` chamado direto no objeto compartilha o mesmo estado e dispara re-render; antes `createWindow` sobrescrevia `config.update/safeUpdate/close/safeClose` e o estado congelava no objeto original (por isso as telas precisavam de `safeUpdate()` defensivos — agora removidos).
- `core.js`: `isSilentStateUpdate` por instância (`_isSilentStateUpdate`) — antes era uma variável de closure compartilhada entre todas as janelas, corrompendo re-renders concorrentes e causando cursor jump.
- `ElementBuilder.js` (`on()`): inputs com `data-bind` usam `_setSilentState` (atualização silenciosa, sem perder foco/cursor).
- `ui/navigation.js` (ActionToolbar): actions agora executam com `this` vinculado à `windowInstance` (`act.action.call(...)`).
- `desktop.js` (`registerStartMenu`/`registerMenuBarMenus`): registro reaplica a UI imediatamente (antes não tinha efeito visível); aceita array puro e `buttonId` customizado. `MenuBar()`/`StartMenu()` escrevem o estado interno direto para evitar recursão render→register→render.

### Novos pontos de extensão
- `ui/navigation.js` (StartMenu e MenuBar): botão direito sobre item de tela emite `menu:screen-context` (`{ screenId, label, icon, x, y }`) via helper `emitScreenContext` para o app oferecer ações (ex.: abrir, criar atalho). `screenId` vem de `screen` ou de `() => openScreen('id')`; `noContextMenu: true` opt-out.
- `ui/navigation.js` (`Shortcut`): visual configurável — opções **`fontColor`** (cor da fonte do label), **`fontSize`** (tamanho), **`fontWeight`** (`'bold'`/número — negrito) e **`fontStyle`** (`'italic'` — itálico), **`backgroundColor`** (cor de fundo do atalho); vazias = cor do tema, aplicadas com precedência sobre a opção `style` genérica. Setters na API: `setFontColor(color)`, `setFontSize(size)`, `setFontWeight(weight)`, `setFontStyle(style)`, `setBackgroundColor(color)` (`''` restaura o tema).

### Comportamento
- `ActionToolbar`: estilo Delphi — botões com ícone exibem só o ícone; o `label` vira tooltip (`hint` tem prioridade). Opt-out por ação: `showLabel: true`.
- `MenuBar` lateral: trilho de ícones — itens com ícone escondem o rótulo (`:has()`), com o texto no `title`; itens sem ícone mantêm o texto.
- `ShortcutContainer`: `direction` (`row`/`column`, +`setDirection`), `reorderable` + `onReorder(ids)`.
- `Desktop.init`: `windowMenuPosition` / `windowToolbarPosition` como padrões das janelas (config da tela tem prioridade).
- `ui/navigation.js`: `positionPopupSubmenu(nested, opt, bounds?)` + `resetPopupPosition(nested)` + `resolvePopupBounds(instance?)` unificam o posicionamento inteligente antes triplicado em ContextMenu/MenuBar/StartMenu (flip, deslocamento, rolagem, limites da janela ou viewport).
- `ShortcutContainer`: `sort` nativo (`asc`/`desc`/`type`/`none` + API `.sort()`); reorder por arrastar com `reorderable: true` + `onReorder(ids)` (direção detectada do flex, indicador visual `.drop-before`).

### Melhorias
- `core.js` (`render()`): aceita `config.render` além de `config.view`; fallback `config.content` no HTML estático.
- `core.js`: proxies `config.update/safeUpdate/close/safeClose` para a instância viva; alias `SecurityService.hasPermission()` → `can()`.
- `ElementBuilder.js`: helper `.eid(key)` (marca `data-eid`).
- `desktop.js`: janelas carimbam `w.dataset.screenId`.
- `ui/data.js` (`Table`): recursos por linha — `onRowClick(row, tr, event)` (a linha ganha a classe `ui-row-clickable` com `cursor: pointer`), `onRowContext(row, tr, event)` (`contextmenu` padrão já vem com `preventDefault`), `contextMenu: (row) => items` (binda o menu do framework na própria linha e expõe `_contextMenuController`) e `rowEvents: { dblclick, ... }` (listeners extras); colunas aceitam `width`/`align` além de `render(val, row)` com string ou Node.

### Plugins (novo)
- `PluginRegistry` (`core.js`): `registerContentHook(fn)` (`{ screenId, root }` a cada render) e `registerMenuItemFilter(fn)` (`{ screenId, kind, labelPath, item } → false` veta). Também via `Framework.registerContentHook/registerMenuItemFilter`. Sem plugins, comportamento idêntico ao anterior.
- `ui/navigation.js`: `filterAuthorizedMenuItems(items, hookCtx)` encadeia caminho de rótulos (`Pai/Filho`); `ContextMenu`/`MenuBar`/`ActionToolbar`/`StartMenu` informam `{ screenId, kind }`.

### Infra
- `package.json` (`desktop-engine@2.1.0`, ESM): `npm run test` (Vitest + JSDOM), suíte inicial em `test/` (segurança, menus, plugins); exports/files com `./format` (módulo de formatação).
- `css/components.css` **removido**: reservatório vazio (só comentário, 0.4 KB) que nenhum código importava — tudo já vive em `core.css`; README e `docs.html` deixam de promover o arquivo.
- `core.js`/`ElementBuilder.js`: acesso ao registry global via escopo SSR-safe (`typeof window`).
